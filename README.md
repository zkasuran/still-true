# Still True?

A knowledge base about Next.js that keeps itself honest, shown two ways.

Framework facts go stale. A router becomes the old way, a default flips, an API turns
async and the old advice keeps ranking in search long after it stopped working. Still True
answers the question a keyword search cannot: not "what does a source say" but "which claim is
current and where do sources disagree".

Live:

- Board + live agent: https://still-true.vercel.app
- Agent only: https://still-true.vercel.app/ask
- Sanity project: `mx12urdz`, public dataset `production`

The agent that answers is **MiniMax-M3**. Next.js is the subject of the knowledge base, not the
engine.

## The idea

Content lives in Sanity as three document types:

- `source` with a publisher, an authority level and a date.
- `claim`, a single factual assertion tied to its primary source.
- `claimEdge`, a typed relationship between two claims: `supports`, `contradicts` or
  `supersedes`, carrying the reason and a confidence.

That last type is the point. A reason for why two claims relate is something a keyword search
can never infer and it is what lets the system mark a fact as superseded or flag two sources as
contradictory.

## Path One: an agent that will not give you a stale answer

`/ask` is an agent that answers only from a Sanity Context Knowledge Base built from real Next.js
source documents. Sanity Context distils them into cited entries and when two sources assert the
same fact incompatibly it raises a conflict rather than guessing.

The agent reads the base through three tools over the Sanity Context client: `list_knowledge` for
the outline, `read_entries` for the cited bodies and `list_conflicts` for the open conflicts. Its
system prompt keeps it grounded, makes it cite the entry paths it used and forces it to surface
both sides when a fact is contested. Ask it whether Next.js caches `fetch` by default and it
gives the current answer (not cached in the App Router), shows that a popular tutorial says the
opposite and says which source wins. Ask about the App Router or async params and it gives the
current guidance and marks the old way as superseded.

The model is MiniMax-M3 over its OpenAI-compatible endpoint. The **Listen** button reads an answer
aloud with MiniMax text to speech.

## Path Two: a board that shows what is settled and what is contested

`/` reads the same claim graph over GROQ and lays it out by topic. Current claims sit above
superseded ones, superseded claims are dimmed and tagged and every `contradicts` or `supersedes`
edge is rendered as a callout with its reason. The Studio in `studio/` models the editorial
process as data with `sanity-plugin-workflow`: a claim moves through `unverified`, `sourced` and
`confirmed`. Only an administrator can confirm it.

## Layout

| Path | What |
| --- | --- |
| `web/` | Next.js app: the board (`/`), the agent chat (`/ask`), the agent API (`/api/ask`) and text to speech (`/api/speak`) |
| `agent/` | The same agent as a standalone CLI |
| `studio/` | Sanity Studio: the schema and the workflow |
| `kb-sources/` | Source documents the Knowledge Base is built from |
| `seed/` | The dataset seed (claims, sources, edges) |

## Run it

```bash
# Studio
cd studio && npm install && npm run dev

# Board + agent
cd web && npm install
cp .env.local.example .env.local   # fill in LLM + Sanity Context creds
npm run dev

# Agent on the command line
cd agent && npm install
cp .env.example .env
npm run ask "Does Next.js cache fetch by default?"
```

The agent talks to any OpenAI-compatible chat gateway (`LLM_BASE_URL`, `LLM_API_KEY`,
`LLM_MODEL`); the live demo uses MiniMax-M3. It reads the Knowledge Base with a Sanity token that
has Context access (`SANITY_ORGANIZATION_TOKEN`).
